# Data Provenance & Metadata Governance

> **SIH PS Vault 2026** · Data Provenance Standard & Governance Guidelines

---

## 🏛️ Data Authority Hierarchy

Data in this repository flows down a strict four-tier authority hierarchy:

```
1. Official SIH 2026 Portal (https://www.sih.gov.in/sih2026PS)
   │ [Live Portal Source]
   ▼
2. Raw Source Snapshot (data/sih2026_raw.html)
   │ [Local offline HTML snapshot of live portal modal dialogues]
   ▼
3. Normalized Dataset (data/sih2026_problem_statements.json)
   │ [Cleaned, UTF-8 encoded, structured JSON dataset]
   ▼
4. Vault Artifacts (01-Problem-Statements/*.md, 02-Themes/*.md, etc.)
   │ [Generated Markdown notes, cross-indexes, and taxonomy catalogs]
```

If the live portal is unavailable or offline, `data/sih2026_raw.html` serves as the verified local source snapshot.

## 📋 Official vs. Derived Metadata

To preserve data integrity, all metadata in the vault is strictly partitioned into **Official SIH Metadata** and **Derived Metadata**.

### 1. Official SIH Metadata (Ground Truth)
These fields are extracted directly from official SIH portal modals without alteration (except for standard whitespace normalization and CP1252/UTF-8 character encoding repair):

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `ps_id` | String | Official Problem Statement ID (e.g. `26001` through `26226`) |
| `title` | String | Official Problem Statement Title |
| `organization` | String | Nodal Ministry, Government Department, PSU, or Industry Partner |
| `department` | String | Sub-department or Ministry division |
| `category` | String | Project classification: `Software` or `Hardware` |
| `theme` | String | One of 18 official SIH themes (e.g. `Smart Automation`, `Space Technology`) |
| `description` | String | Official problem text (parsed into Background, Description, Expected Solution) |
| `source_url` | String | Official SIH portal URL (`https://www.sih.gov.in/sih2026PS`) |
| `dataset_link` | String | Official reference dataset link provided by the nodal org (if applicable) |
| `youtube_link` | String | Official explanatory video link provided by the nodal org (if applicable) |

### 2. Derived Metadata (Vault Enriched)
These fields are computationally generated by vault processing scripts to enable advanced navigation, graph visualization, filtering, and cross-indexing:

| Field Name | Type | Generation Method | Deterministic? |
| :--- | :--- | :--- | :---: |
| `technologies` | List[String] | Keyphrase regex matching over title + description (`vault_config.TECH_KEYWORDS`) | **Yes** |
| `domains` | List[String] | Sector regex matching over title + description (`vault_config.DOMAIN_KEYWORDS`) | **Yes** |
| `organization_type` | String | Org name rule-based classification (`Government`, `Industry`, `PSU`) | **Yes** |
| `has_dataset` | Boolean | Evaluated as `true` if `dataset_link` is present and valid | **Yes** |
| `aliases` | List[String] | Formatted search aliases for Obsidian quick search (e.g. `PS 26001`, `SIH 26001`) | **Yes** |
| `related_problems` | List[Object] | Similarity scoring based on organization, theme, tech, and domain overlap | **Yes** |

---

## ⚠️ Non-Official Disclaimer Rules

1. **Derived fields MUST NOT be presented as official SIH metadata**: Technology tags (`technologies`), sector domains (`domains`), and organization classifications (`organization_type`) are derived analytics provided for explorer convenience.
2. **Deterministic Regeneration**: All derived fields are generated deterministically by `scripts/vault_processor.py`. Modifying keyphrase rules in `scripts/vault_config.py` will update derived tags consistently across the entire vault.
3. **Zero Content Invention**: Vault scripts must never invent missing background text, fake problem statements, or fabricated links.
