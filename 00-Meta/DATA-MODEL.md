# Canonical Data Model & Metadata Specification

> **SIH PS Vault 2026** · Data Model, Field Ownership & Relationship Contract

---

## 1. Overview & Core Entity

The central entity in the **SIH PS Vault** is the **Problem Statement (PS)** record.

A Problem Statement represents an official innovation problem, challenge, or project slot released by the Smart India Hackathon (SIH) 2026 organizing body, issued by a Nodal Ministry, Central Department, Public Sector Undertaking (PSU), or Industry Partner.

Every Problem Statement record captures:
1. **Identity**: Unique identifier and title.
2. **Official Source Metadata**: Fields provided directly by the official portal.
3. **Derived Metadata**: Enriched analytics and classifications generated by vault processing tools.
4. **Graph Relationships**: Links connecting problems to themes, organizations, technologies, domains, and related problem statements.

## 2. Entity Attributes & Classification

### 2.1 Identity Attributes

| Attribute | Type | Example | Description | Authority |
| :--- | :--- | :--- | :--- | :--- |
| `ps_id` | String | `"26001"` | Unique 5-digit SIH Problem Statement ID (`26001` to `26226`). | Official |
| `title` | String | `"AI-based Fundus Image Analysis..."` | Official title of the problem statement. | Official |
| `source_url` | String | `"https://www.sih.gov.in/sih2026PS"` | Direct reference link to the official SIH portal. | Official |

### 2.2 Official SIH Metadata (Ground Truth)

These attributes originate directly from the official portal HTML modals without alteration (except standard CP1252/UTF-8 character encoding repair and whitespace normalization):

- **`organization`** *(String)*: Nodal Ministry, Government Department, PSU, or Industry Partner issuing the problem statement (e.g., `"Ministry of Health and Family Welfare"`).
- **`department`** *(String)*: Sub-division or Ministry department issuing the problem.
- **`category`** *(String)*: Project execution type: `"Software"` (172 problems) or `"Hardware"` (54 problems).
- **`theme`** *(String)*: Official high-level theme category assigned by SIH (1 of 18 themes, e.g., `"MedTech / BioTech / HealthTech"`).
- **`description`** *(String / Object)*: Official problem text content. Parsed deterministically into:
  - `background`: Contextual background provided by the ministry.
  - `description`: Core problem specification.
  - `expected_solution`: Deliverables and outcome expectations.
- **`dataset_link`** *(String)*: Reference URL or dataset path provided by the nodal org (if applicable).
- **`youtube_link`** *(String)*: Official video explanation link provided by the nodal org (if applicable).

### 2.3 Derived Metadata (Vault Enriched)

These fields are computationally generated by vault processing scripts (`scripts/vault_processor.py`) to facilitate navigation, search, and visualization:

- **`technologies`** *(List[String])*:
  - *Description*: Technical stack keyphrase tags (e.g., `["AI-and-ML", "Computer-Vision"]`).
  - *Generation*: Regular expression keyphrase matching over `title + description` (`vault_config.TECH_KEYWORDS`).
  - *Deterministic*: Yes.
  - *False Positives/Negatives*: Possible due to keyword matching limitations.
  - *Authority*: Derived analytics (NOT official SIH metadata).
- **`domains`** *(List[String])*:
  - *Description*: Sector/industry domain classifications (e.g., `["Healthcare"]`).
  - *Generation*: Regular expression keyphrase matching over `title + description` (`vault_config.DOMAIN_KEYWORDS`).
  - *Deterministic*: Yes.
  - *False Positives/Negatives*: Possible.
  - *Authority*: Derived analytics.
- **`organization_type`** *(String)*:
  - *Description*: Org classification (`"Government"`, `"Industry"`, `"PSU"`, `"Other"`).
  - *Generation*: Rule-based lookup against `vault_config.ORG_TYPES`.
  - *Deterministic*: Yes.
  - *Authority*: Derived classification.
- **`has_dataset`** *(Boolean)*:
  - *Description*: Evaluates to `true` if `dataset_link` is present and valid.
  - *Authority*: Derived indicator.
- **`aliases`** *(List[String])*:
  - *Description*: Obsidian quick-search aliases (e.g., `["PS 26001", "SIH 26001"]`).
  - *Authority*: Generated convenience attribute.
- **`related_problems` (`_similar`)** *(List[Object])*:
  - *Description*: Ranked list of top 5 related problem statements with overlap scores and match reasons.
  - *Generation*: Multi-attribute overlap scoring (`organization`, `theme`, `technologies`, `domains`).
  - *Deterministic*: Yes.
  - *Authority*: Derived analytics.

## 4. Canonical Record Definition

The repository distinguishes between ground-truth data, raw snapshots, and generated representations:

```
[Raw SIH Portal]  ──(Scraped)──►  data/sih2026_raw.html  (Raw Source Snapshot)
                                          │
                                     (Normalized)
                                          ▼
                         data/sih2026_problem_statements.json  ◄── CANONICAL GROUND TRUTH
                                          │
                                    (Regenerated)
                                          ▼
                             01-Problem-Statements/*.md  (Generated Markdown Views)
```

1. **`data/sih2026_problem_statements.json` is the CANONICAL GROUND TRUTH DATASET**.
   - Contains all 226 records in machine-readable JSON.
   - Preserves exact clean official text and metadata.
2. **`data/sih2026_raw.html` is the RAW SOURCE SNAPSHOT**.
   - Serves as offline evidence of the raw portal HTML modals.
3. **`01-Problem-Statements/*.md` are GENERATED REPRESENTATIONS**.
   - Note views rendered from the canonical JSON dataset.
   - Should **never** be manually edited individually.

## 5. Relationship Semantics

The vault models five core relationships:

```
                  ┌──────────────┐
                  │    Theme     │ ◄── [belongs_to]
                  └──────────────┘
                         ▲
                         │
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ Organization │ ◄┤   Problem    ├► │  Technology  │
└──────────────┘  │  Statement   │  └──────────────┘
   [issued_by]    └──────────────┘   [classified_as]
                         │
        ┌────────────────┼────────────────┐
        ▼                                 ▼
┌──────────────┐                   ┌──────────────┐
│    Domain    │                   │  Related PS  │
└──────────────┘                   └──────────────┘
[classified_into]                    [related_to]
```

### Relationship Details

| Relationship | Direction | Meaning | Source | Authority | Generated? | Agent Inference Safe? |
| :--- | :--- | :--- | :--- | :--- | :---: | :---: |
| `belongs_to` | PS ➔ Theme | PS belongs to one official theme | SIH Portal | Official | ❌ No | ✅ Yes |
| `issued_by` | PS ➔ Organization | PS was released by this org | SIH Portal | Official | ❌ No | ✅ Yes |
| `classified_as` | PS ➔ Technology | PS uses or requires this tech | Regex Classifier | Derived | ✅ Yes | ⚠️ Caution |
| `classified_into` | PS ➔ Domain | PS belongs to this domain sector | Regex Classifier | Derived | ✅ Yes | ⚠️ Caution |
| `related_to` | PS ➔ PS | PS shares org, theme, tech, domain | Similarity Scorer | Derived | ✅ Yes | ⚠️ Caution |

> [!IMPORTANT]
> **`related_to` Constraint**: The `related_to` relationship is a derived heuristic metric based on metadata co-occurrence. It must **never** be presented as an official relationship established by the Smart India Hackathon organizers.
